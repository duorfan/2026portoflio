# Duorfan portfolio — local rebuild

A local, runnable copy of [www.duorfan.com](https://www.duorfan.com) reconstructed entirely
from a Chrome DevTools Protocol (CDP) crawl. The original site is a Webflow build; this
project preserves the rendered HTML, stylesheets, scripts, images, videos, and fonts
exactly as the browser saw them.

## What's in here

```
.
├── cdp-crawl.js          ← core: scrape duorfan.com via CDP → captured/
├── build-site.js         ← core: captured/ + site-customizations/ → site/
├── server.js             ← core: static server for site/ on :5173
├── package.json
│
├── site-customizations/  ← things you EDIT (overrides, new pages, media)
│   ├── local-overrides.css   (filter chips, AI Builds cards, modal, etc.)
│   ├── local-overrides.js    (filter behavior, password gate)
│   ├── chat-itp.html         (the ChatITP case-study page)
│   └── duorfan-profile-pic.jpg, *.jpg/png/mp4 …   (drop new media here)
│
├── scripts/              ← diagnostic helpers (run via npm run …)
│   ├── verify-site.js        (CDP-driven 404/console check, all 11 pages)
│   ├── shoot-scrolled.js     (screenshot a page after scrolling to a selector)
│   ├── shoot-one.js          (one-shot full-viewport screenshot)
│   ├── shoot-full.js         (full-page screenshot incl. below-the-fold)
│   ├── screenshot.js         (side-by-side local vs live home page)
│   └── probe-filters.js      (click every filter chip + report visible cards)
│
├── captured/             ← GENERATED by `npm run crawl` (raw CDP output)
├── site/                 ← GENERATED by `npm run build` (the runnable site)
└── diagnostics/          ← GENERATED by `npm run verify` / `npm run shoot`
    ├── verify-report.json
    └── screenshots/
```

Generated dirs (`captured/`, `site/`, `diagnostics/`) are gitignored — they're rebuilt from sources.

## Run it

```bash
npm install
npm start
```

Then open <http://localhost:5173>.

## Re-capture from the live site

This is only needed if you want a fresh snapshot. Requires Chrome running with the
DevTools Protocol enabled on port 9222:

```bash
# Launch Chrome with CDP (use a separate profile dir so it doesn't fight your main Chrome)
/Applications/Google\ Chrome.app/Contents/MacOS/Google\ Chrome \
  --remote-debugging-port=9222 \
  --user-data-dir=/tmp/chrome-cdp

# Then in this repo:
npm run rebuild   # crawls → builds → site/ is ready
npm start
```

## Updating the live narrative

These are the things you'll want to tweak as you ship new work:

| What | Where |
| --- | --- |
| The "Now building:" line under the hero | `NOW_BUILDING` constant in [site-customizations/local-overrides.js](site-customizations/local-overrides.js) |
| Scale Social access code | `SCALESOCIAL_HASH` in the same file. Default code is **`duorfan2026`**. To change: run `node -e "console.log(require('crypto').createHash('sha256').update('your-new-password').digest('hex'))"` and paste the hex into `SCALESOCIAL_HASH`. |
| ChatITP case-study copy | Edit [site-customizations/chat-itp.html](site-customizations/chat-itp.html) directly. |
| Add a new AI Film / replace the placeholder | Edit the `AI_FILMS_SECTION` constant in [build-site.js](build-site.js) — drop in a `<video autoplay loop muted>` referring to a `/_assets/...mp4` you've captured. |
| Add a new project to the home page | Edit the relevant `AI_BUILDS_SECTION` or the `applyHomePagePatches` data-tags map in [build-site.js](build-site.js). |
| Footer availability line | `applyFooterAsk` in [build-site.js](build-site.js). |

After any edit: `npm run build && npm start`. Patches are idempotent — re-running won't double anything.

## Filter system

The 7 chips above the project area filter cards by `data-tags`:

- `ai-build`, `ai-film`, `product-design`, `ux-research`, `front-end`, `creative-tech`

Filters are deep-linkable: <http://localhost:5173/#filter=ai-build> jumps in pre-filtered. The same filter bar works on `/more-projects-gallery`; both pages share the JS in `local-overrides.js`.

## Notes

- Responsive `srcset` and `sizes` attributes are stripped during the build, because the
  browser would otherwise prefer a `-p-500.png`-style variant we didn't capture. Only the
  primary `src` image (which we *did* capture) is used.
- `.webm` `<source>` siblings are left pointing at the CDN. Browsers fall back to the
  local `.mp4` automatically when the `.webm` request fails.
- External links (LinkedIn, Instagram, Drive, etc.) are intentionally left untouched.
- The Scale Social client gate is a deterrent, not real security — the page source is downloadable. For true confidentiality on deploy, use Vercel's built-in **Password Protection** (Pro plan) or add a basic-auth check in [server.js](server.js) for `/scalesocial*`.
